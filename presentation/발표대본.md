# Review Insight 소개 대본

본문 17장, 질의응답 부록 1장. 본문은 약 8~10분을 기준으로 조절한다. 교수님 안내 PDF에 PPT·발표 의무는 명시되어 있지 않아 추가 소개 자료로 준비했다.

## 1. Review Insight

안녕하세요. 영화 리뷰의 전체 감성과 구체적인 불만을 함께 분석하는 Review Insight를 소개하겠습니다. 구현한 기능과 실제 학습·평가 결과, 그리고 아직 남은 한계를 중심으로 설명하겠습니다.

## 2. 칭찬과 불만이 한 리뷰에 함께 있다

음악은 좋지만 스토리가 아쉽다는 리뷰는 긍정과 부정 중 하나로만 정리하면 정보가 사라집니다. 이 문제를 해결하기 위해 이용자와 운영자가 리뷰를 읽는 상황을 구체적으로 정의했습니다.

## 3. 영화 비교에서 직접 리뷰 분석까지

서비스는 영화별 분석을 첫 화면으로 제공합니다. 영화 목록에서 작품을 선택하고 평점·감성·불만을 확인한 뒤 두 영화를 비교할 수 있습니다. 마지막으로 새로운 리뷰나 CSV를 입력해 같은 모델로 직접 분석할 수 있습니다.

## 4. 학습용 데이터와 영화별 분석 자료를 구분했다

학습에는 정답이 있는 NSMC를 사용했습니다. NSMC에는 영화 제목이 없으므로 영화별 통계에는 사용하지 않았습니다. 영화별 서비스에는 영화 제목과 실제 평점이 있는 Mendeley 공개 리뷰 이력을 별도로 사용했습니다. 이 표본의 평균 평점은 현재 포털의 전체 평점이 아닙니다.

출처: NSMC: https://github.com/e9t/nsmc ; Mendeley: https://doi.org/10.17632/jb5knzh8yv.6

## 5. 전처리 후 80:10:10으로 고정 분할했다

정규화, 태그·URL 제거, 반복 문장부호 축약, 공백 정리를 구현했습니다. 중복과 상충 정답을 제거한 뒤 seed 42로 층화 분할했습니다. TF-IDF는 학습셋에만 fit했고 검증 F1로 모델을 선택했습니다.

출처: reports/data_audit.json ; reports/preprocessing_examples.csv

## 6. 단어 모델과 문자 모델을 직접 학습했다

단어 모델을 베이스라인으로 두고 문자 n-gram 모델을 비교했습니다. 문자 표현은 띄어쓰기와 어미 변화가 있는 한국어 단문에 대응하려는 선택입니다. 두 모델의 C는 같은 검증셋에서 선택했습니다. Transformer를 학습한 것처럼 설명하지 않겠습니다.

출처: reports/training_environment.json ; reports/comparison.csv

## 7. 문자 모델의 테스트 F1은 0.8688이었다

목표는 테스트 F1 0.80 이상이었습니다. 단어 모델은 0.8093, 문자 모델은 0.8688로 문자 모델이 약 0.0596 높았습니다. 선택은 테스트가 아니라 검증 F1에 기반했습니다. 이 수치는 긍정 클래스의 이진 감성 성능이며 불만이나 혼합의 성능이 아닙니다.

출처: reports/comparison.csv

## 8. 문자 표현은 검증 F1에서 더 좋은 결과를 보였다

이 그래프는 epoch별 loss가 아니라 학습 표본 수별 F1 곡선입니다. 각 지점에서 특징 추출기와 모델을 다시 학습했습니다. 데이터가 늘 때 검증 F1은 개선됐지만 학습과 검증 사이의 격차는 남아 있습니다.

출처: reports/learning_curves.png ; reports/*_learning_curve.csv

## 9. 짧은 표현과 복합 문맥에서 오류가 남았다

문자 모델의 혼동행렬입니다. 부정 7,325개 중 6,409개, 긍정 7,272개 중 6,289개를 맞혔습니다. 짧은 표현인 뷁은 부정을 긍정으로 오분류했습니다. 감정과 영화 외 상황이 섞인 문장도 한계가 있었습니다.

출처: reports/char_lr_confusion.png ; reports/char_lr_errors.csv

## 10. 실제 이용자 평점과 모델 감성은 다른 지표다

영화별 분석에서는 원 자료의 이용자 평점과 모델 감성 비율을 나란히 보여줍니다. 예시로 택시운전사와 공조를 비교할 수 있습니다. 수치는 일부 공개 리뷰 이력의 표본이므로 전체 관객 선호로 일반화하지 않습니다.

출처: web/data/catalogue.json ; https://doi.org/10.17632/jb5knzh8yv.6

## 11. 불만 유형은 복수 분류와 표본 분모를 반영했다

한 리뷰에는 연기와 스토리 불만이 함께 있을 수 있습니다. 각 범주의 수는 그 범주로 분류된 리뷰 수이며 비율의 분모는 해당 영화의 분석 리뷰 총개수입니다. 합계가 100퍼센트를 넘을 수 있습니다.

출처: web/data/catalogue.json ; src/catalogue.py

## 12. 혼합 리뷰는 절별 모델 예측을 조합했다

이 문장은 전체 이진 모델로는 부정에 가깝습니다. 하지만 음악 절은 긍정 가능성 63.46퍼센트, 스토리 절은 6.40퍼센트입니다. 서로 반대되는 절이 함께 있어 혼합으로 표시하고 불만은 스토리만 남깁니다. 별도의 3클래스 모델을 학습한 것은 아닙니다.

출처: reports/mixed_review_checks.json

## 13. 높은 불만 점수를 정확도처럼 보여주지 않았다

불만 레이블은 자동 규칙으로 만든 약한 레이블입니다. 따라서 99.9퍼센트 같은 분류 점수를 실제 정확도라고 해석할 수 없습니다. 제한된 문맥·부정어 대조 12건 중 3건은 기대와 달랐습니다. 독립 사람 정답이 없어 불만 F1과 확률 보정은 수행하지 않았습니다.

출처: reports/model_context_audit.json ; reports/aspect_training.json

## 14. 사전 계산과 직접 분석에 같은 가중치를 쓴다

영화 목록과 상세 결과는 미리 계산한 JSON을 읽어 시연 지연을 줄입니다. 직접 입력은 같은 TF-IDF와 회귀 가중치를 브라우저에서 계산합니다. 모델 해시와 분석 기준을 검사합니다. 영화별 실제 리뷰 20건을 비교했을 때 Python과 JavaScript의 최대 확률 차이는 약 5.57 곱하기 10의 마이너스 9승이었습니다. 실제 브라우저 및 오프라인 동작 검증은 완료하지 못했습니다.

출처: reports/movie_browser_parity.json ; web/models/analysis_manifest.json

## 15. 개발 과정에서 확인한 점

좋았던 점은 동일 분할 비교와 실제 영화 제목 연결 자료를 확보한 것입니다. 아쉬운 점은 사람 정답이 없어 불만 성능을 검증하지 못한 점과 표본 편향입니다. 흥미로웠던 점은 한 리뷰에 칭찬과 불만이 공존한다는 점, 높은 별점과 문장 감성이 다른 점입니다.

## 16. 남은 한계를 구분하고 개선 순서를 정했다

혼합 리뷰를 이진 결과로만 보여주던 문제는 절별 재예측을 추가해 보완했습니다. 긍정 문장이 불만으로 표시되는 문제는 부정 절 중심 표시로 줄였습니다. 다만 사례 수정은 정답셋 성능 개선의 증명이 아닙니다. 다음 단계는 사람 정답 구축, Transformer 비교, 실제 화면·모바일·오프라인 시연 점검입니다.

## 17. 시연 순서

발표 시연은 이 순서로 진행하면 됩니다. 영화 목록에서 공조를 선택하고 수록 리뷰 평점, 감성 비율과 불만을 확인합니다. 택시운전사를 비교에 추가해 두 영화를 비교한 다음 직접 리뷰 분석에서 혼합 사례를 입력합니다. 인터넷이 불안정하면 미리 분석된 결과와 이 자료의 실제 표를 사용하면 됩니다.
